# experiments

Воспроизводимые прогоны, на которые ссылаются разборы в `../references/`. Код — стандартная библиотека Python, без зависимостей.

Запуск всего набора: `bash run_all.sh` (или по одному скрипту из каталога эксперимента).

| эксперимент | что доказывает | опорный разбор |
| --- | --- | --- |
| `phantom-join/` | набор тестов может быть зелёным 6 из 6, пока выход повреждён: выпадение на JOIN (сирота, ключ с пробелом) и фантомные записи (дубль в справочнике размножает агрегат); критерии надёжности в журнале ловят то, чего тесты не видят | `../references/diagnostics-over-tests-dirty-data.md` |
| `model-probe/` | модель без указаний пишет шапку-контракт модуля, секционирует код и документирует только нетривиальные функции; в агентной обвязке сама восстанавливает цикл «написал → прогнал → поправил» | `../references/sft-code-training-and-module-contracts.md` |

## phantom-join

1. `python3 demo.py` — наивная трансформация (INNER JOIN без нормализации ключей и без дедупликации справочника) и типичный happy-path набор тестов. Печатает результаты тестов, что ушло на выход и что было в данных на самом деле.

Ожидаемый итог: **6 из 6 PASS** при истине 1030 против 665 в отчёте (дельта −365), завышение по ACME ×2 из-за дубля в справочнике.

2. `python3 run_log.py` — тот же прогон, но пишет **только журнал** `run.jsonl` (стадии `source.orders → source.dim → join → agg → write`).
3. `python3 evaluate.py` — оценка **только по журналу и `criteria.json`**, без доступа к исходным данным.

Ожидаемый итог: 4 тревоги и вердикт «НЕ ПРИНЯТО», причём критерий `crit.sum.invariance` получает статус **«непроверяемо»** — в журнале нет поля `orphan_amount`.

4. `python3 run_log.py --orphan-amount && python3 evaluate.py` — тот же прогон с одним добавленным полем. Критерий становится проверяемым: непроверяемых нет, вердикт «НЕ ПРИНЯТО» остаётся.

Это и есть демонстрация тезиса LDD: **не хватает поля в контексте — критерий слепой; добавили поле — критерий работает.** Лечится расширением логирования, а не новым тестом.

## model-probe

`python3 analyze_probe.py` — счётчики по файлу `probe_taskqueue.py` (строки, шапка модуля, секции, доля документированных функций). Происхождение артефакта — в `model-probe/PROVENANCE.md`; файл — результат пробы, а не продакшн-код.

## Что не коммитится

Файлы, которые скрипты создают при прогоне (`orders.csv`, `customers.csv`, `report.csv`, `run.jsonl`), перечислены в `.gitignore` — они воспроизводятся заново.
