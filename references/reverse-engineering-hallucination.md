# Галлюцинация при реверс-инжиниринге: верная идея, выдуманный API

> Наблюдение автора GRACE (Владимир Иванов, август 2026). Разбор сессии
> frontier-модели (Gemini), которой дали реверс-инжиниринг кода DSH. Блок
> «Верификация» — редакторская вставка с фактами исходников, не текст автора.

## Ситуация

Frontier-модели дали задачу: разобрать архитектуру DeepSeek Harness (DSH) по
исходникам. В ответ — связный, уверенный, детальный разбор механик работы с
длинным контекстом: «Persistent vs Ephemeral context», «Checkpoints», «Compaction
& Revert», «KV Cache на SSD/HBM». Выглядело как честный реверс-инжиниринг.

Сверка с кодом показала: высокоуровневая идея верна, а конкретный API выдуман.

## Что модель придумала (в коде отсутствует)

| Утверждение модели | Реальность |
|---|---|
| тег `ephemeral: true` на выводе инструментов | Нет. Единственный литерал — флаг Codex-треда (`subagent-codex/wire.ts`), не тег сообщения. Роль играет append-only проекция `surfaceOp` + два редьюсера |
| фазы скилла `commit()` / `rollback()` («скилл write-module говорит: после commit() Фаза 1 очистится») | Нет. `packages/skill/` таких фаз не содержит |
| агент вызывает `checkpoint()` → рантайм сворачивает Scope | Нет такого API. «Checkpoint» — результат суммаризации (compaction-basic, head-range, `<compacted-summary>`), авто-запуск по `thresholdRatio 0.8`, а не ручной вызов агентом |
| KV Cache хранится на SSD/HBM, сервер «вытаскивает» из SSD/RAM | Нет. DeepSeek-кэш серверный, автоматический, prefix-based; клиент только репортит хит (`cacheReadTokens`), cache-write метрики нет |

## Что модель угадала верно (источник правдоподобия)

- Cordis = revertible effects + LIFO dispose + HMR — реально, но это «commit/rollback»
  на уровне плагинов/эффектов, а не сообщений/скиллов. Модель перенесла реальную
  концепцию на выдуманный message-level API.
- Log vs Surface (append-only) — реально, но через `surfaceOp`, не через тег.
- Prefix-кэш: инвалидируется только хвост от первого изменённого токена, префикс
  тёплый — дословно совпадает с README «KV Cache effect».
- MLA (DeepSeek/Kimi) — реальный факт, но он про уменьшение размера KV, а не
  «хранение на SSD».

## Мета-вывод

Вокруг ВЕРНОЙ высокоуровневой идеи (разделение persistent/ephemeral, чекпоинты,
append-only, префикс-кэш) модель уверенно достроила КОНКРЕТНЫЙ API, которого не
существует. Правдоподобность максимальна, фактов ноль. Это ровно тот режим
«anthropology trap»: модель выдаёт убедительный связный нарратив о чужой системе,
не сверяясь с первоисточником.

Следствия для практики GRACE:

1. Реверс-инжиниринг чужого кода силами LLM — гипотеза, а не факт. Любое
   утверждение на уровне API (имя тега, фаза, вызов) подлежит проверке grep'ом по
   исходникам ДО использования в документе или решении.
2. Верная абстракция ≠ верная реализация. Модель хорошо ловит идею (persistent vs
   ephemeral, транзакции), но реализацию додумывает.
3. Cross-LLM проверка сама по себе не спасает: вторая модель может подтвердить
   правдоподобную ложь. Спасает только сверка с источником.
