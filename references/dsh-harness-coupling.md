## I. Архитектура: DSH как «React для бэкенда»

DeepSeek Harness фактически работает в логике «React для бэкенда». Cordis, на котором
он построен, — enterprise-технология для сложных решений. Общее с React: оба работают
через TypeScript и проповедуют state-философию. Если на фронте «рендеринг state»
интуитивно понятен, то для бэкенда это более сложная абстракция — и DSH сам по себе
учит масштабируемым, отказоустойчивым архитектурам. Одна из важнейших фишек Cordis:
при сбое плагина он умеет автоматически откатывать state.

Почему это удобно для ИИ. Во-первых, аналогия с React и общий язык TypeScript
позволяют модели опереться на огромный корпус, на котором она обучалась. Во-вторых,
если у модели есть нативное состояние (state-space LLM с рекуррентным скрытым
состоянием), то слово «state» здесь не случайно общее. Важная оговорка: структура
этого состояния иная, чем у Cordis/React, и агент не может адресно читать или писать
в скрытое состояние модели — это аналогия, задающая направление мышления, а не
механизм, напрямую снижающий число ошибок.

## II. Продукт: агент-перетачиваемая «болванка» + доменщик

DeepSeek Harness собрал свыше 100 000 звёзд за первые дни после публикации (сама по
себе эта метрика — сигнал интереса, а не качества). Девиз «Everything is a Plugin»
стал сердцем экосистемы: в интерактивной сессии любой компонент можно редактировать
через ИИ-агента или создать новый без перезапуска — включая UI, UX и любую деталь.

Это не «фреймворк», а «болванка»: фундамент будущих AI-продуктов. Её можно, например,
допилить под умного Excel/SQL-ассистента, работающего с ERP. Болванка превращается в
инструмент в руках узкопрофильного специалиста, который знает болевые точки своей
области и снимает их с помощью ИИ. Здесь же стратегическая развилка: DeepSeek не
ставит целью сделать инструмент «для чайников» — эталоном служит то, что команда на
своём же Harness создаёт код для собственных целей; обучение дилетантов — следствие,
а не стартовая цель.

Ключевые возможности, которые выделяет автор: любые LLM-провайдеры; рой субагентов и
динамический роутинг моделей под задачу; полный доступ к системным промптам и tools;
перехват/отклонение запросов к LLM (кибербез); кастомизация UI (интерактивные
компоненты в чате, кнопки, инжект в слоты, замена React-компонентов); клик по DOM →
добавление в контекст → агент правит код по превью. Этот список пересекается с
существующими агентскими средами, поэтому отличие не в наборе фич, а в инверсии:
агент переписывает сам харнесс.

## III. Эпистемика: качество модели связано с харнессом

Эксперты отмечают: результаты Terminal Bench заметно меняются в зависимости от того,
каким агентом гоняют модель, — раньше такого эффекта не проявлялось. Это указывает не
на «предобучение на агента», а на пост-тренинг (RL) на агентных траекториях: модель
оптимизирована под конкретный харнесс, поэтому на чужом — деградирует. Сам DeepSeek в
сносках указал: для корректного воспроизведения Terminal Bench нужен минималистичный
агент (только Bash и редактор) — именно он использовался как «скоростной» в пайплайне
обучения.

В контраст приводят Anthropic: периодически утверждается, что их модель обучена на
Claude Code, но, как говорят, из их же публикаций видно обратное — для чемпионских
результатов в SWE-Bench используется специальный агент с приёмами multi-attempt и
временных тестов, и обычным Claude Code это не воспроизвести из-за иного агентского
пайплайна с перерасходом токенов. Это утверждение требует ссылки на конкретную
публикацию — ниже помечено как непроверяемое.

Практическое следствие: Terminal Bench на удивление хорошо проходит именно в DeepSeek
Harness, и вокруг этого уже появляются готовые решения — agent-пресеты, переносящие
«режим бога» конкретной модели в конкретный харнесс.

harness-coupling и деградация на чужом агенте), а не свойство базовой модели.

## Выводы для GRACE

1. **Тройная связка**: AI-native разработка = модель × харнесс × доменщик. Харнесс —
   та часть, которую сейчас систематически недооценивают.
2. **Harness-coupling**: бенчмарк больше не «чистое» свойство модели. Любую таблицу
   результатов читать через призму «каким агентом гоняли и каким надо гонять».
3. **Точность терминов**: «предобучение на агента» → RL; «агент модифицирует себя» →
   инспекция рантайма + mount/unmount плагинов.
4. **Доменщик = оружие**: профи-фёрст (DeepSeek) против ноуб-фёрст (Anthropic) —
   реальная стратегическая развилка, а не риторика.
5. **Хайп vs durable**: звёзды, «нет предела», «костыль» — маркетинг. Durable-инсайт —
   harness-coupling и тройная связка; их и фиксировать в каноне.
6. **РФ-факт**: DSH — один из немногих крупных агент-харнессов, работающих без VPN
   (DeepSeek API доступен).
