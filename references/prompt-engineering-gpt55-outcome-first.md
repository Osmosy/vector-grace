# Промпт-инжиниринг для GPT-5.5 — outcome-first подход

> Разбор официального руководства OpenAI по промптингу GPT-5.5 от Пименова.
> Оригинал: https://pimenov.ai/knowledge/prompt-inzhiniring-gpt-5-5-outcome-first-podkhod/

## Ключевая идея

**От режиссуры процесса к постановке задачи.** GPT-5.5 — переход от стажёра к старшему специалисту. Пошаговые инструкции сужают пространство решений, outcome-first — расширяет.

> "Раньше мы писали модели сценарий. Теперь пишем ТЗ."

## Структура системного промпта (каркас OpenAI)

```
Role: [1–2 предложения: функция модели, контекст и задача]
# Personality
[тон, манера и стиль взаимодействия]
# Goal
[видимый пользователю результат]
# Success criteria
[что должно быть верно до финального ответа]
# Constraints
[ограничения: политика, безопасность, бизнес, доказательства, побочные эффекты]
# Output
[разделы, длина и тон]
# Stop rules
[когда повторить, откатиться, воздержаться, спросить или остановиться]
```

Главное правило: каждая секция короткая. Если в Constraints 30 правил — половина устарела.

## Reasoning effort

| Уровень | Когда | Сигнал поднять |
|---------|-------|----------------|
| **low** | Факты, классификация, трансформации | Путается в многошаговой логике |
| **medium** | Дефолт для агентских задач | Ошибки в длинных цепочках |
| **high** | Архитектура, многофакторный анализ | — |

Начинать с low, поднимать только при необходимости.

## Personality vs Collaboration style — два разных слоя

**Personality** — как модель звучит (тон, теплота, юмор, эмпатия).
**Collaboration style** — как модель работает (когда уточняет, когда решает сама, проактивность).

Не смешивать. Иначе — тёплый, но парализованный ассистент.

### Пример: task-focused

> Предпочитай двигаться вперёд, а не останавливаться ради уточнений, если запрос уже достаточно ясен. Опирайся на контекст и разумные предположения.

### Пример: коллаборативный

> Предлагай собственную точку зрения, а не просто отражай пользователя.

## Outcome-first промпт

**Как нужно:**
```
Реши вопрос клиента от начала до конца.
Результат достигнут, когда:
- решение принято на основе доступных данных
- все разрешённые действия выполнены
- финальный ответ содержит completed_actions, customer_message и blockers
```

**Как не нужно:**
```
Сначала изучи A, потом B, потом сравни, потом реши, потом вызови инструмент...
```

## Жёсткие правила — только для инвариантов

`ВСЕГДА` / `НИКОГДА` / `ALWAYS` / `NEVER` / `must` / `only` — только для:
- Правил безопасности
- Обязательных полей вывода
- Запрещённых действий

Для всего остального — **decision rules** (решающие правила, отдающие выбор модели).

## Stopping conditions

```
Решай запрос за минимальное число полезных циклов вызова инструментов,
но не ставь экономию циклов выше корректности.
После каждого результата спрашивай себя: «Могу ли я уже ответить?»
Если да — отвечай.
```

Без этого блока агенты склонны к лишним итерациям.

## Retrieval budget

```
Для обычных вопросов начинай с одного широкого поиска.
Делай повторный поиск только когда:
- результаты не отвечают на основной вопрос
- не хватает конкретного факта/даты/ID
- пользователь попросил полный список
- нужно прочитать конкретный документ
Не ищи повторно ради улучшения формулировок или примеров.
```

Последний абзац — самый важный. Он отрезает «давай ещё поищу для красоты».

## Валидация через инструменты

```
После внесения изменений запусти наиболее релевантную проверку:
- юнит-тесты на изменённое поведение
- линтер/типы
- сборку пакетов
- smoke-тест
Если проверку запустить нельзя — объясни почему.
```

## Пример миграции: было → стало

**Было (legacy):**
> Сначала прочитай вопрос. Потом обязательно сделай поиск. Потом прочитай все статьи. ВСЕГДА ищи минимум два раза. Потом обязательно перепроверь.

**Стало (outcome-first):**
```
# Goal
Реши вопрос пользователя по базе знаний.
# Success criteria
- Ответ опирается на найденные статьи
- Если нет ответа — честно скажи
# Retrieval
Начни с одного поиска. Повторный — только если не хватает.
# Stop
Как только можешь ответить — отвечай.
```

## Связь с GRACE

| OpenAI / Пименов | GRACE |
|-----------------|-------|
| Outcome-first | Примат замысла, PCAM |
| Decision rules | Controller/Worker, уникальные теги |
| Validation через инструменты | verification-before-completion |
| Retrieval budget | Grep-first, PwC |
| System prompt skeleton | SKILL.md frontmatter |
| Personality vs Collaboration | — (можно добавить) |

Статья — независимое подтверждение GRACE-подхода от OpenAI. То, что GRACE формулирует через XML-артефакты и семантическую разметку, OpenAI формулирует через outcome-first промпты и stopping conditions. Суть одна: **не диктуй процесс, описывай результат**.
