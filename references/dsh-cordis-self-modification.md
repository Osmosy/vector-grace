# DeepSeek Harness: самомодифицирующийся агент на Cordis

> Эссе автора GRACE (Владимир Иванов, август 2026). Основано на анализе
> deepseek-ai/deepseek-harness и статьи cordiverse/paper. Блок «Верификация» —
> редакторская вставка с фактами по состоянию на 15.08.2026, не текст автора.

## Тезис: новая парадигма, а не «ещё один агент»

Сейчас главное событие в профессиональном ИИ — не очередные обновления LLM и
бенчмарки (это идёт непрерывно), а решение DeepSeek по агентской обвязке с
самомодифицирующимся на лету кодом на плагинах. Поддержку дала академическая
статья Пекинского университета. Репозиторий deepseek-harness набрал уже свыше
100 000 звёзд на GitHub (точную цифру не фиксируем — растёт ежедневно).

Архитектор PostgreSQL Олег Бартунов согласился в LinkedIn, что это технологический
прорыв, и рассматривает включение аналогичного в свой SQL-сервер.

## Суть подхода: «американцы идут тупиковым путём»

Основная идея: фиксированные плагины, требующие перезагрузки системы, — тупик.
Новая парадигма — агент сам изменяет свой код on the fly. Для этого нужен
интерпретируемый язык: DeepSeek применил TypeScript, с декларациями плагинов
примерно такого вида:

```ts
// Пример концептуального плагина в парадигме Cordis
export function apply(ctx: Context, config: Config) {
  // 1. Потребление коэффектов (зависимостей):
  ctx.using(['database'], (ctx) => {
    // 2. Генерация обратимого эффекта (Revertible Effect):
    ctx.on('message', (msg) => { ... });
    // 3. Предоставление собственного сервиса
    ctx.plugin(MySubPlugin);
  });
}
```

## Связь с опытом автора

Автор около года в обучении говорит о будущем за плагинными системами агентов,
где агенты самомодифицируют код на лету. Предлагались решения на Python с
передачей объекта БД как «контекста» (ERP-подобные задачи). Здесь важнее
философия: получать самомодифицирующиеся приложения как обычный софт. Это не
чудо — LLM уже достаточно мощны, чтобы писать себе агентский код.

## Верификация (редакторская вставка, 15.08.2026)

Факты по состоянию на дату (сверено по исходникам deepseek-ai/deepseek-harness,
репозиторию cordiverse/paper и GitHub API):

- Репозиторий реален: `deepseek-ai/deepseek-harness`. Звёзды — свыше 100K и
  быстро растут (≈113K на 15.08.2026, ~2 дня с момента публикации; точную цифру
  в долгоживущих документах не фиксировать).
- Cordis подключён как vendored-фреймворк (`vendor/cordis`). README DSH дословно:
  «everything is a plugin, powered by Cordis».
- «Самомодификация» подтверждена и даже буквальнее, чем в эссе:
  `packages/extensions/README.md` — «the agent modifies its own runtime»;
  `packages/README.md` — «Agent runtime self-modification: live plugin/service
  inspection and model-written plugin mount/unmount». Есть демо
  `pnpm run demo:cordis — the agent modifies its own runtime`.
- Статья — `cordiverse/paper`, «A Programming Paradigm for Spatiotemporal
  Composability» (препринт, драфт 13.08.2026, ~1.6K★). Описывает ровно revertible
  effects + reactive coeffects + HMR.
- «Пекинский университет» подтверждён: в `paper.pdf` на первой странице стоит
  «Peking University».
- TypeScript — да (ESM, `.ts`, tsx-лаунчер).
- Пример плагина из эссе (`apply` / `ctx.using` / `ctx.on` / `ctx.plugin`) —
  корректный Cordis-API, ровно так пишутся плагины в DSH.

Тонкая поправка к формулировке «агент сам изменяет свой код on the fly»: точный
механизм — агент инспектирует свой рантайм и монтирует/демонтирует плагины,
написанные моделью (dynamic composition), а не переписывает произвольный исходник.
Показательно, что сам проект 11.08 переименовал группу `self-modification/` →
`extensions/`, записав в решении: «extensions states the stable package role
without asserting that the agent modifies itself». Тезис по сути верен, но точнее
говорить «инспекция рантайма + mount/unmount model-written плагинов».

Непроверяемое: согласие Олега Бартунова (реальный архитектор PostgreSQL / Postgres
Pro) — LinkedIn-цитата извне не проверяется. «Американцы идут тупиковым путём» —
риторика/оценка, не факт.

## Выводы для GRACE

1. Тезис автора подтверждён продакшеном дословно — механизм прямо назван
   «self-modification» в коде (до переименования в `extensions/`).
2. Точность формулировок важна: «агент модифицирует себя» команда сама смягчила
   до «инспекция + mount/unmount плагинов». Придерживаться той же точности.
3. Быстрорастущие метрики (звёзды, версии) в durable-доках писать как «>N, растёт»,
   а не точным числом.
