# HTML-документация для AI-агентов

> Эссе Владимира Иванова (TurboPlanner) — почему HTML как формат документации побеждает Markdown для LLM-агентов, и как это связано с GRACE.

## Проблема

Читая разработчиков Anthropic в X, Владимир заметил тренд: многие переходят с Markdown на HTML-документацию. Несмотря на больший объём, HTML оказывается эффективнее для работы с LLM.

## Почему HTML лучше Markdown для агентов

### 1. Sparse attention

HTML с его XML-подобной структурой даёт чёткие семантические границы, которые GPT распознаёт лучше, чем плоский Markdown. `<div class="warning">`, `<code data-line="42">`, `<section id="architecture">` — это не украшение, а **семантические якоря** для sparse attention трансформера.

Трансформеру легче установить корреляцию между идентичными токенами открывающего и закрывающего тега на больших расстояниях — это семантически «сшивает» удалённые части документа.

### 2. Визуализация

HTML позволяет встраивать:
- Mermaid-диаграммы через CDN-скрипт
- Интерактивные таблицы с сортировкой
- Сворачиваемые секции (`<details>`)
- Цветовую маркировку (warning/error/info)
- Chart.js дашборды

В Markdown для этого нужны HTML-вставки — и тогда зачем Markdown?

### 3. "Add Element to Chat" в VS Code

Ключевое открытие: если HTML-документация открыта во встроенном браузере VS Code (Live Preview), появляется функция **Add Element to Chat**. Это превращает документацию в интерактивный UI для агента:

1. Клик на элементе диаграммы
2. "Add Element to Chat"
3. Агент получает DOM-контекст этого элемента

В Sequence Diagram можно ткнуть в блок → агент расскажет, о чём речь. Если код уже создан — перебросит прямо к строке.

> «Это просто феерически мощный механизм, если вы сверстали документацию в HTML и смотрите в VS Code»

## Связь с GRACE

GRACE изначально построен на XML-артефактах (DevelopmentPlan.xml, knowledge-graph.xml, MODULE_CONTRACT). HTML-документация — естественное расширение той же идеи:

- **Семантические теги** — те же уникальные закрывающие теги GRACE (`</M-MODULE>`), только в HTML-обёртке
- **Sparse attention** — HTML-структура работает как семантические маяки, аналогично GRACE-разметке в коде
- **Интерактивность для агента** — Add Element to Chat = GRACE-верификация через DOM

## Вывод: гибридный подход

Оптимальный вариант — **не "или-или", а конвейер**:

```
Код → Docstrings (машинный минимум) → HTML-дока (человек + агент)
```

- Docstrings остаются для IDE-подсказок и быстрой справки
- HTML-документация — для глубокого погружения, визуализации архитектуры, sequence diagrams
- Data-атрибуты в HTML — для интерактивной работы через агента в VS Code
