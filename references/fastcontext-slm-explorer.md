# FastContext — SLM для поиска в кодовых базах

> Эссе Владимира Иванова (TurboPlanner) — про FastContext от Microsoft: специализированная SLM для repository exploration, которая отделяет поиск от решения задачи.

## Что это

**FastContext** — семейство специализированных exploration-моделей от Microsoft (4B–30B параметров) на базе Qwen3. Модель обучена с Reinforcement Learning для длинных траекторий поиска в репозиториях, но строго в read-only сценарии.

**Ключевая идея:** отделить repository exploration от code solving. В обычных coding-агентах одна и та же модель и ищет код, и решает задачу — в результате 56.2% всех tool-use turns и 46.5% токенов уходит на чтение/поиск, засоряя контекст.

FastContext — выделенный exploration subagent, который:
- Умеет только **READ / GLOB / GREP** (три read-only инструмента)
- Обучен стратегии **параллельного запуска** инструментов
- Отвечает строго в формате `<final_answer>` — компактные file:line-range
- **Не использует CoT** — сразу вызывает инструменты поиска

## Почему это важно

1. **SLM не думает, а делает** — без CoT, сразу параллельные вызовы инструментов. На RTX 5080: ~70 tok/s на генерацию, 2500 tok/s чтение контекста, влезает 50K токенов.
2. **Стратегия поиска SLM отличается от LLM** — модель иногда находит неочевидное для большой модели, потому что ищет иначе. Они работают в паре.
3. **Практичный пример SLM в production** — не игрушечный, а для больших кодовых баз.

## Загадка удаления

Microsoft внезапно удалил оригинальный репозиторий и модель без объяснения причин. Но сообщество уже утащило — в квантированных вариантах (mradermacher) скачали более 120 000 раз.

Вероятная причина: обычная Gemma 4 12B NVFP4 работает умнее и может делать выводы, хотя контекста загружает меньше. Но сам паттерн (SLM-explorer + LLM-solver) показан убедительно.

## Связь с GRACE

FastContext — прямое подтверждение GRACE-принципа **разделения ролей** (Controller/Worker). В терминах GRACE:
- FastContext = exploration worker (только READ/GLOB/GREP)
- Основной coding agent = controller/solver
- `<final_answer>` = формальный контракт между ними

Тот же паттерн, что и в GRACE: специализированный агент с ограниченным инструментарием, жёстким форматом вывода и чёткой границей ответственности.
