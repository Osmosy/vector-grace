# DeepSeek Harness: восстановимый контекст вместо «бесконечного»

> Тезис автора GRACE (Владимир Иванов, октябрь 2026), переданный как наблюдение об
> архитектуре памяти DSH: «у ИИ бесконечный контекст — сессия сама сжимается, но ИИ
> может лазать по прошлому логу хоть на 100M токенов».
> Блок «Верификация» — редакторская вставка с фактами по состоянию на 04.10.2026,
> не текст автора.

## Тезис

Контекст в DSH не «бесконечный» в буквальном смысле — он **восстановимый**. Разница
принципиальная: обычное окно теряет то, что из него вытеснено; здесь ничего не теряется
безвозвратно, потому что прошлое лежит в отдельном durable-логе и доступно по запросу.

## I. Почему это работает: журнал как источник истины

Ключ — не размер окна, а то, что история сообщений для модели **выводится** из
append-only журнала событий (`SessionEvent`), а не хранится отдельно. В доке
`docs/subsystems/session.md` это сказано прямо: «The LLM message history is *derived*
from the log, never stored separately; replay is re-derivation from the same events».

Отсюда три следствия, которых не даёт обычный контекст:

1. **Журнал durable.** JSONL-файл на сессию, сжатый zstd-фреймами, `fsync` на каждый
   батч (`docs/subsystems/persistence.md`). Перезапуск процесса не уничтожает историю.
2. **Компакция — плагин, а не часть ядра.** `dsh-compaction` / `compaction-basic` —
   отдельная capability seam. Ядро агентского цикла о ней не знает; её можно заменить
   или не ставить вовсе.
3. **Компакция прячет, а не удаляет.** Сжатый диапазон помечается `shadowedSeqs` —
   он перестаёт идти в модель, но остаётся в журнале. Это принципиально отличается от
   «сжали и забыли»: данные не уничтожаются, они перестают *подставляться*.

Именно поэтому «лазать по прошлому» технически возможно: прошлое не выброшено, оно
отодвинуто.

## II. Как агент достаёт прошлое

В наборе инструментов DSH есть **`session-query`** — «Literal full-text query over
prior session history», с фильтрами по идентификаторам сессий и диапазону времени
создания (`docs/tool-catalog.md`). Это не «модель помнит всё» — это поиск по журналу
как по базе.

Практическая разница:

| Обычный контекст | Журнальный подход DSH |
|---|---|
| вытесненное исчезает | вытесненное ищется |
| «помню / не помню» | «спросил / не спросил» |
| размер окна = потолок | потолок = объём журнала на диске |
| сжатие необратимо | сжатие = сокрытие витрины |

Последняя строка в таблице — суть. Компакция в DSH обратима в том смысле, что
уплотнённая часть остаётся доступной отдельным инструментом.

## III. Что это меняет в проектировании агента

Тезис автора ценен не как «у DSH больше контекст», а как смена опоры:

- **Память перестаёт быть борьбой за окно.** Задача не «уместить», а «не потерять
  при упаковке» — и упаковка перестаёт быть точкой невозврата.
- **Перезагрузка становится управляемой.** Если прошлое лежит в журнале, а инструкции
  для агента — в его собственном файле (`AGENTS.md` в DSH), то «мануал для
  перезагрузки» — это не костыль, а штатный артефакт: агент восстанавливает не
  «воспоминание», а процедуру.
- **Few-shots важнее описаний.** Обороты речи и примеры вызовов восстанавливают
  поведение точнее, чем пересказ правил: модель копирует форму, а не выводит её из
  абстракции.
- **Отчётность становится частью памяти.** Раз история — журнал событий, а не
  транскрипт переписки, качество работы видно машинно, а не по «правдоподобному»
  тексту сессии.

## Верификация (редакторская вставка, 04.10.2026)

Проверено по репозиторию и документации, не по пересказу.

- `deepseek-ai/deepseek-harness`: **243 334★**, 29 167 форков, MIT, создан **13.08.2026**,
  `pushed_at` **03.10.2026**. Описание: «DeepSeek Harness: Everything is a Plugin».
  Организация `deepseek-ai` — реальная, 44 репозитория (DeepSeek-V3 104 514★, R1 91 932★).
- Архитектура на **Cordis**, статус — **developer preview**: в README прямо
  «THERE WILL BE COMPATIBILITY-BREAKING CHANGES», плюс отдельный `SAFETY.md`.
- Журнал сессии — append-only `SessionEvent`; история для модели производится из него
  (`session.md`). Персистентность — JSONL на сессию, zstd-фреймы, `fsync` на батч
  (`persistence.md`).
- Компакция — **отдельный плагин** capability-seam, не ядро агентского цикла;
  уплотнённое помечается `shadowedSeqs` и не удаляется из журнала (`compaction.md`).
- Доступ к прошлому — инструмент **`session-query`** с параметрами `query`,
  `session_ids`, `created_at_from/to` (`tool-catalog.md`).

**Что НЕ подтвердилось.** Цифра «100M токенов» в документации **отсутствует** (поиск
`100M`/`million tokens` по `docs/` — пусто); «ИИ сам лазает по логу» тоже не
специфицировано — доступ идёт вызовом инструмента, то есть по инициативе агента, а не
автоматически. Обе формулировки — **оценки автора**, а не заявления проекта. Полезно
и то, что их можно проверить: механизм реален, числа — реконструкция.

## Выводы для GRACE

1. **Термин «бесконечный контекст» неточен; правильный — «восстановимый контекст».**
   Он описывает то же явление точнее и не обещает невозможного: объём всё равно
   ограничен диском, но потеря при упаковке не окончательна.
2. **Приём переносим без смены харнесса.** Идея «компакция прячет, а не удаляет» +
   «прошлое доступно поиском» работает и там, где журнал не является единственным
   источником истины. Это методология, а не свойство конкретного продукта.
3. **Мануал для перезагрузки — правильный артефакт, и не только для DSH.** Если
   агент после сжатия восстанавливается файлом, а не памятью, то такой файл нужно
   писать заранее — пока сессия не переполнилась. Few-shots с оборотами речи в нём
   важнее описаний правил.
4. **Смена модели только между этапами остаётся в силе.** Журнальный подход усиливает
   эту дисциплину: откат состояния плагина и восстановление из журнала — разные
   операции, и путать их нельзя.
