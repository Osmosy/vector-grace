# Агентские тесты не меняют исход: SWE-bench Verified, 6 моделей

**Дата записи:** 2026-10-18
**Источник (эссе пользователя):** пересказ исследования ByteDance / SJTU / SMU с графиком «отключение тестов в бенчмарках» и тезисом «консенсус учёных: тесты ИИ — мусор».
**Первоисточник (проверен по HTML v2):** `arXiv:2602.07900` — **Rethinking the Value of Agent-Generated Tests for LLM-Based Software Engineering Agents** (Zhi Chen, Zhensu Sun — SMU; Yuling Shi, Xiaodong Gu — SJTU; Chao Peng — ByteDance; David Lo, Lingxiao Jiang — SMU). v1 — 2026-02-08, v2 — 2026-04-09; в шапке v2 указана конференция (октябрь 2026, Washington, DC).

## Дизайн (а не «отключение тестов в бенчмарке»)

1. **Наблюдение:** 6 сильных моделей на SWE-bench Verified (500 задач) под `mini-SWE-agent`, тесты необязательны. Топ-модели на 2025-12-11: Claude Opus 4.5 (74.4%), Gemini 3 Pro (74.2%), GPT-5.2 (71.8%), Kimi K2 Thinking (63.4%), MiniMax M2 (61.0%), DeepSeek v3.2-R (60.0%).
2. **Интервенция:** prompt — просить писать больше или меньше тестов (4 модели). Это не удаление тестов из бенчмарка: доля задач с тестами меняется на 37.0–75.2%, не на 100%.

## Числа (таблицы 1, 7; текст RQ3)

| что | значение |
|---|---|
| Claude 4.5: доля задач с новыми тестами | 83.0% (415/500), 74.4% решено |
| GPT-5.2: доля задач с новыми тестами | 0.6% (3/500), 71.8% решено |
| задачи, сохранившие исход после интервенции | 83.2% |
| значимость сдвига исхода, все 4 модели | p > 0.05 (точный McNemar) |
| DeepSeek v3.2-R, discourage | тесты убраны в 376 задачах, **−20 решённых**, p = 0.435 |
| Gemini 3 Pro, encourage | p = 0.522, небольшой минус |
| Kimi K2-T, discourage | p = 0.228 |
| GPT-5.2, encourage | 9 fail→success против 9 success→fail, net 0, p = 1.000 |
| цена у Kimi (discourage) | input −49.0%, API-вызовы −35.4% |
| цена у DeepSeek (discourage) | input −32.9% |
| цена у GPT-5.2 (encourage) | +19.8% output-токенов без прироста |

Вывод авторов: «more tests do not mean more solves»; тесты работают как observational feedback (value-revealing print встречается намного чаще assert-проверок); улучшать надо оракулы, а не количество тестов.

## Где эссе перегибает

- «Отключить вообще все тесты в классических бенчмарках» — нет: prompt-интервенция на SWE-bench Verified, 68–75% задач.
- «Последние версии SWE-тестов» — нет: DeepSWE и ProgramBench — другие бенчмарки, не SWE-bench.
- «p = 0.435 у Kimi и DeepSeek» — p = 0.435 только у DeepSeek; у Kimi 0.228.
- «Консенсус: тесты ИИ — мусор» — в статье мягче: агентские тесты — привычный ритуал процесса, а не надёжный источник валидации.

## Практика

Мерить надо не «сколько тестов написал агент», а стоимость валидации и качество оракула. Прирост качества от объёма самотестов не наблюдается; наблюдается рост токенов.

Смежное: `tdflow-human-vs-llm-tests.md` (там разрыв 68.0% против 94.3% объясняется долей некорректных тестов, а не авторством), `kun-chen-tdd-and-ground-truth.md` (TDD на ProgramBench: −3.6 п.п., p < 0.0001), `unit-test-only-reward-degradation.md` (unit-test-only как награда в RL).
