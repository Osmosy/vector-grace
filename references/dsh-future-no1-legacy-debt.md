## Тезис: до конца августа DSH станет №1 агентом кодирования по звёздам

По текущей таблице звёзд GitHub для агентов кодирования DSH обгонит
opencode до конца августа. Строго говоря, DSH — самая быстрорастущая
разработка в истории GitHub по этому критерию: растёт быстрее OpenClaw
(≈13,5K★/день против ~1,4K★/день в среднем по жизни, т.е. на порядок).
А раз так — у DSH есть претензия не только на агента кодирования, но и
на универсального агента.

## Почему старые агенты не справятся даже с плагинами на JS

Понять это — значит увидеть, что текущие агенты несут огромный
технический долг из-за изначально неоптимальной архитектуры. Попытки
приставлять что-то «сбоку» (как в Codex) скептически воспринимаются
разработчиками — видно по звёздам: пользователи даже больше
предпочитают сейчас архитектуру Pi как тренд.

У DSH огромное преимущество перед устаревающими за день архитектурами
за счёт промышленного ядра плагинов Cordis. Три составляющих:

1. **Hot reload всегда.** Cordis позволяет перегружать плагины на лету,
   без перезапуска; значительная часть старых агентов для многих кейсов
   требует перезагрузку всей системы. Для самомодифицирующегося агента
   это критично: не выходя из агента, сразу получать результат
   очередной модификации.
2. **Аварийная устойчивость Enterprise-класса.** Cordis автоматически
   откатывает упавшие плагины и чистит за ними память. Связи плагинов
   и декларация зачистки — обязательные вещи. При ставке на
   самомодификацию неизбежны ошибки ИИ в создаваемых плагинах — и
   архиважно, чтобы такие ошибки обрабатывались максимально безопасно
   с точки зрения надёжности. Это не вайб-кодинг на коленке с
   loop engineering, когда автор даже не смотрит, что агенты творят
   внутри агента, и публично этим гордится.
3. **Кастомизация 100% системы.** Никакой другой агент не даёт такой
   кастомизации: в DSH вся система — плагины. В реале нормальный
   уровень кастомизации в Open Code почти всегда требует форк. В DSH —
   конфигурация, а не форк.

## Надёжность самомодификации: React-генерализация

Отдельный момент — надёжность программирования ИИ при
самомодификации. Cordis на TypeScript с его state-подходом весьма
аналогичен React (см. `dsh-harness-coupling.md`). Практический эффект:
все LLM за счёт генерализации подтягивают к разработке DSH свои
чудовищного объёма знания из обучения на React. Итог — надёжность
создания плагинов на лету: модель пишет плагин в знакомой ей парадигме,
а ядро гарантирует, что даже ошибочный плагин не рушит систему
(revertible effects + автоматический откат).

## Прогноз

DSH уже осенью будет лидирующим открытым агентом — причём со
значительным расширением из области агента кодирования к
универсальному.

  «самая быстрорастущая среди агентских платформ» надёжнее (историю

- **«Pi как тренд»** — подтверждено: pi (earendil-works) 98 710★,
  форки/обвязки растут (oh-my-pi 28K★, pi-web 5,5K★, pi-skills 2,4K★).
  Сигнал: пользователи голосуют за минималистичный, чистый agent loop.
- **«Hot reload всегда»** — подтверждено: HMR плагинов, mount/unmount
  без перезапуска (см. `dsh-cordis-self-modification.md`: revertible
  effects + инспекция рантайма).
- **«Автоматический откат и зачистка памяти»** — подтверждено
  архитектурой Cordis: обратимые эффекты (revertible effects) с
  автоматическим откатом при выгрузке плагина; декларативные коэффекты
  (зависимости) обязательны при регистрации.
- **«В Open Code кастомизация почти всегда = форк»** — правдоподобно,
  прямых данных нет (оценка из практики; opencode — форк-фёрдли
  продукт, форки 2,3K+). Непроверяемо строго.
- **«React-генерализация повышает надёжность ИИ-плагинов»** — теоретический
  тезис, прямых бенчей нет. Косвенно: официальная документация DSH
  опирается на знакомые TS/React-паттерны; demo «the agent modifies its
  own runtime» в репо.
- Про loop engineering и «публично гордится» — риторика/оценка автора;
  как факт не верифицируется (позиция Бориса Чёрного из публичных
  выступлений/постов).

## Выводы для GRACE

1. **Скорость ≠ зрелость, но скорость = окно.** Рекордный рост даёт DSH
   окно доминирования, которое конкуренты могут закрыть только
   перестройкой архитектуры — на это у них месяцы, окно закроется
   раньше.
2. **Технический долг — необратимое преимущество.** Старые агенты
   не могут «переставить» архитектуру: долг Claude Code/Codex — не
   фича, которую добавляют, а фундамент, который надо сносить.
   Отсюда скепсис разработчиков к «приставкам сбоку» и дрейф к Pi.
3. **Тройная защита самомодификации** = hot reload (мгновенный
   результат) + revertible effects (безопасный откат) + React-
   генерализация (надёжный код от LLM). Это делает
   самомодифицирующегося агента практикой, а не демо.
4. **Расширение к универсальному агенту** уже видно в реестре: IM-боты,
   голосовой ввод, медиа, знание-графы — плагины выходят за пределы
   кодинга (см. `dsh-algorithm-vs-prompt-agents.md`, раздел dshai.org).
5. **РФ-факт** остаётся: DSH работает без VPN, в отличие от
   claude-code/codex/cursor.
