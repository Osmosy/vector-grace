# Finam Hermes Trading Bot («Герман»): агент готовит — код и человек исполняют

Source: pzzz404/finam-hermes-trading-bot — https://github.com/pzzz404/finam-hermes-trading-bot (MIT, создан 12.08.2026). Разбор: Osmosy, 02.09.2026, по клону репо. Контекст: конкурс «Финам Арена 2026» (1 июня — 31 июля, три портфеля по 1 млн виртуальных рублей, сделки по реальным котировкам через Finam Trade API); агент «Герман» публиковался в интервью Finam.ru 27.06.2026.

## Главный паттерн

**Агент делает intelligence-работу, consequential-шаги исполняют детерминированный код и человек.** Герман сканирует рынок, формулирует гипотезы, проверяет риск, сохраняет решения и шлёт отчёты в Telegram — но не может «просто купить». Мутация брокера закрыта несколькими независимыми замками, и агент не имеет права их открыть.

Это реализация схемы prepare → gates → human approval на финансовом домене —
та же структура, что consequential gates в vector-legal (драфт готовит агент,
отправку делает человек) и delegation-gate-checklist (least privilege).

## Проверено в коде (не декларация, а реализация)

| Механизм | Где | Как работает |
|---|---|---|
| Двойной live-gate | `safety.py` | `TRADING_MODE != live` → `LiveTradingBlocked`; плейсхолдер/demo account id → блок. Мутация отклоняется на низком уровне клиента — один случайно добавленный `--live` торговлю не открывает |
| Confirmation phrase | `execution.py` | заявка требует точную фразу подтверждения, несовпадение → `OrderNotAllowed("confirmation_required")` |
| Детерминированный risk | `risk.py` | чистая функция: allowed_tickers, max_daily_loss, max_order_value, max_position_value, short по умолчанию запрещён. LLM-оценка «вспомогательная и не снимает risk-gates» |
| Обучающий слой | `arena_learning.py` | decision-snapshots + execution-ledger (JSONL) → learning report/proposal: статистика решений и ошибок — не декоративная |
| Read-only по умолчанию | `mcp_readonly.py`, отдельные скрипты | сетевые read-only проверки вынесены из основного CLI; `pytest --disable-socket` — тесты физически не могут достучаться до сети |
| Инженерная гигиена | CI | Gitleaks + pip-audit + CodeQL; `redaction.py` маскирует credentials; `PUBLIC_SHA256SUMS.txt`; systemd-юниты по умолчанию в paper/dry-run |

Объём: ~8 500 строк библиотеки + 11 100 строк `hermes_operator.py` (CLI-адаптер к Hermes). 89 файлов, 6 сервисов systemd (pulse, growth-loop, executor, runtime-doctor и др.).

## Шесть уровней системы (из интервью Finam.ru)

1. рыночный сканер (инструменты, ликвидность, волатильность);
2. торговая гипотеза (вход, риск, сценарий, условие отмены);
3. риск-контроль (размер позиции, просадка, право запретить сделку);
4. исполнительный контур (подтверждения и проверки перед заявкой);
5. обучающий слой (статистика решений, сделок, ошибок);
6. человек над системой (рамки эксперимента, защита от «казино»).

Поведенческий ориентир: агент чаще говорит «не торговать», чем «срочно покупать».

## Чему учит проект (переносимые правила)

1. **Multi-gate mutation** — несколько независимых замков (глобальный режим
   + не-плейсхолдер счёта + confirmation phrase + отдельные env-флаги),
   каждый на своём уровне. Один скомпрометированный флаг не открывает
   consequential-действие.
2. **Read-only by construction** — сетевые проверки отдельно, тесты без сети.
3. **Risk — детерминированная функция**, а не промпт. LLM только предлагает.
4. **Journal всех решений** — материал для обучения и разбора ошибок.
5. **Юниты безопасные by construction** — копирование unit-файла не включает
   торговлю.
6. **Честные ограничения в README** — не обещать доходность, не публиковать
   токены и историю сделок.

Это ровно та же архитектура, что: consequential gates в vector-legal (драфт
готовит агент, отправку делает человек), least privilege в delegation
(enabled_toolsets), human approval перед production в Vector AI Team.

## Оценка проекта

Сильно: gates на уровне методов клиента (не на уровне «агент обещал»);
обучающий слой с реальными ledger; инженерная гигиена выше среднего
(отключение сокетов в тестах, сканирование секретов, redaction). Роль агента
честная — подготовка и проверка, не самостоятельная торговля.

Слабо/ограничения: результаты торговли не публикуются (автор честно пишет,
что это не доказательство стратегии); Finam API может менять wire format;
поддержка не гарантируется; звёзд мало (4) — проект недооценён как инженерный
артефакт.

## Связь с экосистемой Vector

- **vector-legal**: consequential gates — та же схема (плагин готовит драфт,
  отправку делает человек; патентный поверенный обязателен).
- **delegation-gate-checklist**: multi-gate перед spawn = multi-gate перед мутацией.
- **vector-ai-team**: Герман — образцовый пример роли агента с ограничениями
  и детерминированной проверкой.
- **vector-home** (умный дом): тот же принцип — агент предлагает, система
  ограничивает, человек утверждает.
