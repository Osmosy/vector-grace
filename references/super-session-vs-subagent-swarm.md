# Суперсессия против роя субагентов: философия DSH

> Эссе автора GRACE (Владимир Иванов, август 2026). Основано на анализе
> deepseek-ai/deepseek-harness. Блок «Верификация» — редакторская вставка
> с фактами исходников, не текст автора.

## Тезис

DSH по факту придаёт анафеме субагентов. Все решения, построенные на массе
субагентов, стали мусором. Идея DSH — суперсессия: одна долгоживущая тёплая
сессия, у skills есть правила компактизации и удаления из контекста после
отработки. Это совсем другая философия, а привычный «рой субагентов» здесь не
работает.

## Что отвергает DSH

DeepSeek по факту говорит: привычный рой субагентов — грубейшая ошибка
проектирования, потому что он:

- губит KV Cache — каждый новый субагент стартует холодным prefill'ом, общий
  тёплый префикс не переиспользуется;
- замедляет и удорожает инференс — тот же контекст пересчитывается заново на
  каждом субагенте;
- не пользуется крупными контекстами современных LLM — вместо одного длинного
  окна работа дробится на N холодных изолированных запусков.

Правильная единица — долгоживущая сессия с правилами компактизации и
on-demand-загрузкой скиллов, а не рой воркеров.

## Верификация (редакторская вставка, 15.08.2026)

Сверено по исходникам deepseek-ai/deepseek-harness (клон от 15.08.2026):

- Тезис по сути верен, но формулировка «анафема субагентов» — перебор. DSH НЕ
  запрещает субагентов: есть целая подсистема `ctx.subagents` с шестью
  провайдерами (`subagent-spawn-in-process`, `-fork`, `-acp`, `-codex`,
  `-claude-code`, `-dsh-sdk`).
- Отвергается конкретный паттерн — рой ОДНОРАЗОВЫХ (`one-shot`) субагентов,
  каждый из которых стартует холодно. Решение DSH — не «ноль субагентов», а
  переизобретение субагента: `continuable` (durable child Session + резидентная
  Activation + холодный resume → у ребёнка свой тёплый префикс между вызовами).
- «Суперсессия» — наш описательный ярлык (из разбора «DSH: суть механизмов
  долгоживущей сессии»), НЕ термин DSH. В коде слова нет: grep `super-session`
  даёт только `supersession` в session-title — в смысле «отмены/замещения», про
  другое. Реальная механика — agent-presets standing-mount + тёплый FRAME +
  continuable-дети.
- «Правила компактизации у скиллов» — это не правило самого скилла, а два
  generic-редьюсера: `tool-result-pruner` (8192/4096/1024) и `compaction-basic`
  (thresholdRatio 0.8, retainRatio 0.16). Тело скилла грузится on-demand в хвост
  и потом подпадает под общую компактизацию; отдельного механизма «скилл удаляет
  себя после отработки» нет.
- Цена continuable: каждый ребёнок добавляет секцию в system-prompt
  (prefix-cost), список детей растёт линейно → «пул держать узким».

## Выводы для GRACE

1. Точная формулировка: «анафема рою one-shot субагентов», а не «анафема
   субагентам вообще». DSH не запрещает — переизобретает (continuable, тёплый
   префикс, узкий пул).
2. Верная абстракция требует точной реализации — и наоборот: верную идею легко
   исказить, подав её как «субагенты запрещены». Это обратная сторона наблюдения
   про галлюцинацию при реверс-инжиниринге: там выдуманный API портил верную
   идею, тут неточная формулировка портит верную идею.
3. «Суперсессия» держать как внутренний ярлык GRACE, но в доке ссылаться на
   реальные механизмы (standing-mount, continuable, warm FRAME), а не на термин.
