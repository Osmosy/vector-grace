## Суть

Навык TDD из самого популярного набора агентских навыков (`obra/superpowers`, **301 087 звёзд** на 17.10.2026, MIT — в эссе было «297.0k», цифра просто устарела) прогнали через ProgramBench в режиме «одна модель — два плеча»: свободный выбор подхода против обязательного test-first. Результат — **строгое доминирование контроля**: TDD хуже по качеству и дороже по деньгам одновременно, на всех уровнях сложности.

## Числа (первоисточник, n = 192 задачи)

| метрика | control | TDD | Δ |
| --- | ---: | ---: | --- |
| средний pass-rate, % | 52.4 | 48.8 | **−3.6 п.п.** (парный Wilcoxon, p < 0.0001) |
| задач выиграно / проиграно / ничья | — | — | 53 / **136** / 3 |
| $ за задачу | $1.12 | **$1.73** | **+55 %** |
| ходов (turns) | 40 | 67 | **+69 %** |
| solve@75, % | 13.5 | 9.9 | −3.6 |
| выходные токены | — | — | +26 % |
| **входные токены** | — | — | **+112 %** |
| **ходы рассуждения** | — | — | **+248 %** |

- Хуже всего на **лёгких** задачах: −5.3 п.п. при +69 % стоимости — когда задача тривиальна, test-first это чистые накладные расходы.
- Механика роста счёта («деньги покупают процесс, а не продукт»): каждый микроцикл red-green-reftactor — отдельный ход, который заново оплачивает весь контекст.
- Разбор примеров: `json-tui` 82 → 46 — TDD выбросил `termios`, `select` и живой цикл TUI (интерактивный терминал юнит-тестом не покрыть, а правило «никакого кода без падающего теста» не дало его написать); `eureka` 67 → 38 — 13.7 КБ тестов против 4.7 КБ реализации, «минимальный код, чтобы позеленело» удалял поведение; `csview` $0.91 → $3.00 при неизменном качестве.
- Оговорки автора: одна модель (gpt-5.5), один навык, один тип задач (black-box reverse-engineering CLI по бинарнику и документации), one-shot с скрытым спеком, повторов по задачам нет; агрегат крепкий, отдельные задачи — иллюстрации. «Это не артефакт бюджета»: все TDD-прогоны завершались нормально с зелёными своими тестами.

## Failure mode (главное, а не проценты)

Агент не может написать достаточно тестов, чтобы покрыть требования, которых он не знает: «проходит мои тесты» превращается в «готово». Само-тесты подтверждают сами себя, а не поведение — тот же вывод у Böckeler, которая наблюдала тавтологичные тесты, пересчитывающие ожидаемое значение той же логикой, что и реализация.

Родственный эксперимент того же автора (та же обвязка): четыре принципа через AGENTS.md («Think Before Coding, Simplicity First, Surgical Changes, Goal-Driven Execution») — 53.7 → 51.5 % (−2.2 п.п., p = 0.005), 79 побед / 111 поражений / 2 ничьи, стоимость +5 %. Гайдлайны не упростили код, а **сузили объём**: «простота прежде всего» толкуется буквально, краевые случаи тихо выбрасываются, встроенные движки (SQLite) заменяются самоделками. Формулировка автора: «он рассуждает себя в неполноту».

## Тезисы эссе поверх цифр

1. **Хайп при выборе навыков.** Инженеры ставят наборы навыков из популярных репозиториев, не проверяя, есть ли тесты, доказывающие, что навык работает. Отдельное исследование того же автора (`superpowers-bench`) измеряет уже другой срез: находит ли агент нужный навык сам (`obra/superpowers`, плечи «без подсказки» / «с подсказкой»).
2. **Тесты в приложениях агентам не помогают.** Если запрет писать новые тесты чуть повышает точность фиксов, то полное отключение всех существующих тестов (unit и integration, включая ручные) в бенчмарках вроде DeepSWE почти не меняет вероятность фикса — ни в плюс, ни в минус. Текущая тестовая обвязка приложений для агента бесполезна. *(В публичном репо `programbench-bench` этот эксперимент не описан — там два исследования: языки и TDD; сведения идут из треда, первоисточник по нему не подтверждён.)*
3. **Без тестов агент уходит на ground truth.** Логи, реальные данные приложения, телеметрия; чтобы вообще запускать код — MCP, CLI, Playwright. Автор эссе ведёт это к методике NASA 1972 года: формальные «сферические» тесты тестируют код как абстракцию и не воспроизводят среду, поэтому акцент сместили на замеры данных от датчиков. *(Оценка/историография эссе, документально не проверена — в таком виде не подтверждается; проверяемо только общее «test like you fly» + опора на телеметрию.)*
4. **Ошибка выжившего.** То, что практика «как-то работает» у обычного оператора агентов (приложение запустилось — значит, практика хороша), — не доказательство её эффективности.

## Что проверить и чем это можно опровергнуть

- **−3.6 п.п. — это про конкретный срез:** black-box reverse-engineering по скрытому спеку, one-shot, без долгоживущей кодовой базы. Обычная выгода TDD (известный спек + регрессионная защита) из этой постановки вырезана намеренно.
- **Навык в эксперименте — снапшот, а не сегодняшний апстрим.** Хеши не совпадают: плечо TDD несёт `test-driven-development/SKILL.md` 9 867 Б (`7a751fa9…`) + `testing-anti-patterns.md` 10 715 Б; текущий апстрим — 9 578 Б (`46838cc9…`) + `writing-good-tests.md` 8 268 Б (`d3c4482f…`) — то есть в апстриме файл, на который ссылается эссе, появился позже, а у плеча раздел «Why Order Matters», которого в апстриме уже нет. Наша локальная копия — третий снимок: `SKILL.md` 12 069 Б (`3df9ab81…`).
- **«Деградация 3–10 %»** — подтверждается лишь частично: в отчёте −3.6 п.п. в среднем и −5.3 п.п. на лёгких; «10 %» в публичных материалах нет.
- **«Перерасход до 80 %»** — не подтверждается: отчёт даёт +55 % стоимости и +69 % ходов (на лёгких +69 % стоимости). Похожая цифра «3×–8.5× токенов» — из другого эксперимента (Böckeler).
- **«OpenAI деградируют жёстче, чем Anthropic»** — сравнение живёт в треде, в отчёте репо его нет (там модель держат фиксированной по построению).

## Подтверждённые цифры из смежных работ (та же тема «мерить, а не верить»)

- Böckeler (martinfowler.com, авг. 2026): агентский TDD на трёх задачах, слепая оценка Opus — не-TDD решения заняли большинство верхних мест, расход **3×–8.5× токенов**, тавтологичные тесты; рекомендация — mutation testing, статический анализ, структурные ревью.
- JetBrains / Денис Ширяев (июль 2026): «caveman» — обещали −65 % выходных токенов, измерили −8.5 % (при k=1 было −29.5 %, на трёх повторах −6.7 %); «RTK» — дашборд обещал 96.2 млн сэкономленных токенов, фактический счёт вырос на +7.6 %; «ponytail» — единственный реальный сигнал: медианная стоимость −10.3 %, длина кода −15.4 % (обещали −54 %).
- Anthropic (июль 2026): у Claude Code вырезали >80 % системного промпта для моделей 5-го поколения без измеримой деградации на кодинг-эвалах.
- Boris Cherny (автор Claude Code): «каждые полгода удаляй свой CLAUDE.md, свои навыки и хуки» — возвращай инструкцию только под наблюдённый отказ.
- Гипотеза Ivett Ördög: в обучающих данных много пар «требование → готовая функция» и почти нет настоящих TDD-трасс, поэтому принудительный TDD борется с выученным способом работы модели.

## Выводы для практики агентов

1. **Навык = гипотеза, а не улучшение.** Ставить наборы навыков «потому что популярно» — то же, что ставить зависимость без тестов: цена видна только на своём workload, в парном измерении и на повторах (k ≥ 3).
2. **Проверять не процесс, а результат.** Красный тест, который агент написал себе сам, доказывает лишь факт запуска; у человека он снимает страх и даёт design pressure — агенту это недоступно.
3. **Где TDD остаётся осмысленным:** известный спек, долгоживущая кодовая база, регрессионная защита, тесты как контракт между людьми. Именно эти условия в эксперименте были вырезаны.
4. **Ставка на измеримость:** детерминированные проверки вне модели (линтеры, статические анализаторы, структурные ревью, mutation testing), а не наращивание процессных инструкций.
5. **Ground truth вместо самооценки:** логи, метрики, телеметрия, реальные данные из работающего приложения — и инструменты, которыми агент может это добыть (MCP, CLI, браузерный раннер).
6. **Инструкции имеют срок годности:** модель меняется, вчерашняя лучшая практика становится сегодняшним налогом.
