# «Всё — плагин»: архитектура агентского харнесса DeepSeek

> Эссе автора GRACE (Владимир Иванов, август 2026). Основано на анализе
> deepseek-ai/deepseek-harness (113K★ на 15.08.2026, 2 дня с момента публикации).
> Блок «Верификация» — редакторская вставка с фактами репозитория, не текст автора.

## Тезис: концепция подтверждена продакшеном

DeepSeek выпустил собственную агентскую обвязку (deepseek-harness, `dsh`) и тем
самым подтвердил концепцию, которую автор продвигал в обучении около года:
**для ИИ оптимальная архитектура — «всё является плагином».**

Фактически агентская среда DeepSeek ультимативно подходит к этой идее:
модели, инструменты, навыки, сессии, песочницы, файловые системы, циклы,
оркестрация и UI — **всё реализовано исключительно как плагины**.

## Почему это важная концепция

Уже несколько лет наблюдается де-факто разочарование в завышенных ожиданиях от
микросервисов. Изначально они позиционировались как средство построения крупных
приложений из «разбивания монолитов». В реальности получились крайне кривые
«распределённые монолиты»:

- замедление обмена между серверами;
- архисложные распределённые транзакции;
- весь этот over engineering — ровно на пустом месте.

Поэтому последние годы шла тенденция забирать приложение целиком: если
Web-сервис, то весь.

Оставался вопрос: **как тогда структурировать крупные приложения** — особенно с
учётом того, что ИИ нативно (SFT, ~90% времени) пишет «маленькие сложные
программы» примерно на 100–200 строк. Поэтому очень важно сводить задачу для ИИ
к этим маленьким изолированным фрагментам кода.

## Плагины как ответ

Плагины в чём-то стали ответом на этот запрос:

- для них есть масса паттернов, в том числе **«Плагин = Tool»**;
- в решении DeepSeek показано, что **все абстракции агента можно свести к
  понятию плагина** — от модели до agent loop и UI;
- маленький изолированный фрагмент кода = естественная единица для ИИ, и
  плагин как раз такая единица: самодостаточен, подключается и отключается,
  не требует понимания всего монолита.

## Потенциал против Claude Code

Надо посмотреть внимательней, но очень вероятно, что DeepSeek может начать
обыгрывать Claude Code в качестве агента. После утечки (Борис Черни) выяснилось,
что внутри Claude Code царит «сказочный бардак и лапша-код». Однако агенты
стремительно обрастают функциональностью, и **правильная архитектура здесь
может стать ключом к эффективности**: пока функциональность мала, хаос в коде
не мешает; когда агент обрастает десятками подсистем — архитектура решает.

## Верификация (редакторская вставка, 15.08.2026)

Факты репозитория по состоянию на дату:

- `deepseek-ai/deepseek-harness`: 113 203★, 10 995 fork, MIT, TypeScript,
  создан 13.08.2026. Developer preview: `npx @deepseek-ai/dsh web` → UI на :3080.
  npm `@deepseek-ai/dsh` — 0.1.0-rc.6 (6 версий). В README прямо предупреждение:
  «THERE WILL BE COMPATIBILITY-BREAKING CHANGES».
- 0 открытых issues (перенесены в Discussions). Монолит из 49 пакетов
  (acp, api, code-runtime, compaction, fs, guard, jobs, llm, lsp, …).
- Архитектурный документ подтверждает тезис автора дословно: «Every part of the
  product is a plugin, including the model adapter, the tool registry, the
  session log, and the agent loop itself — every part is replaceable from
  configuration».
- Фундамент — не собственная разработка: [Cordis](https://github.com/cordiverse/cordis)
  (3.9K★, TypeScript, MIT, с 2022) — «Meta-Framework of Spatiotemporal
  Composability» с одноимённой статьёй. dsh доводит зрелую IoC-идею до предела:
  профили = композиции плагинов, эффекты с автоматическим откатом при выгрузке
  плагина, JSONL event sourcing, песочницы Landlock.
- Известные болячки (Discussions): web_fetch выключен по умолчанию → агенты
  падают на bash+curl и блокируются WAF/CDN (#323); approval-поп-ап может не
  появиться → бесконечное зависание tool call (#2105); session persistence
  ломается на Android/Termux из-за SELinux (#2106).

Контрапункт (обсуждение #326, «the user-side cost»): «всё — плагин» — отличный
питч для разработчиков, но для конечного пользователя это конфигурационная
сложность (профили, бандлы, кто какой сервис предоставляет). Claude Code —
один бинарь, ноль конфигурации. Плагин-конфликты неизбежны при 49 пакетах:
A зависит от сервиса B, B от хука C, C обновился — сломал D.

## Выводы для GRACE

1. Концепция «маленькие сложные программы» (100–200 строк) получает
   производственное подтверждение: единица разложения для ИИ = изолированный
   плагин, а не сервис и не класс в монолите.
2. Архитектура агента — конкурентное преимущество по мере роста функциональности;
   «лапша» допустима только пока агент мал.
3. Компромисс «разработчик vs конечный пользователь» — плагин-всё решает
   первое и усложняет второе; граница пролегает там, где конфигурацию берёт на
   себя сам ИИ (генерирует композицию профиля), а не человек.
4. Для РФ важный факт: это один из немногих крупных агент-харнессов, работающих
   без VPN (DeepSeek API доступен), в отличие от Claude Code/Codex/Cursor.
