# Mermaid для bird's-eye контроля над решениями ИИ

> Наблюдение автора GRACE (Владимир Иванов). Записано 2026-07-04.

Когда ведёшь разработку с ИИ, важно быстро визуализировать, ЧТО он собрался сделать.
Максимальный риск — не в его ошибках, а в том, что мы не все требования предъявили.
ИИ как «мастер додумывания» сам добавляет компоненты решения, но его «наиболее вероятно»
лишь вероятно, а не обязательно правильно. Значит нужен контроль за ИИ в проектировании.

ИИ создаёт огромное количество спеков и кода с чумовой скоростью — читать их бесперспективно,
нужны визуализации класса **bird's-eye view**. Хороший вариант — **Mermaid**: поддерживается
почти всеми агентами. В нём куда больше диаграмм, чем обычно знают: агенты сами применяют лишь
2-3 из 26 доступных. (В конкретном агенте 3-4 beta-типа могут не работать — тестируйте.)

## Каталог 26 типов Mermaid для визуализации решений ИИ

| Тип | Синтаксис | Для чего |
|---|---|---|
| Flowchart | `graph`/`flowchart` | Блок-схемы, алгоритмы, деревья решений, связи компонентов |
| Sequence | `sequenceDiagram` | Взаимодействие участников во времени (клиент-сервер, API, процессы) |
| State | `stateDiagram-v2` | Жизненный цикл объекта, статусы и переходы |
| Class | `classDiagram` | UML классов: атрибуты, методы, наследование, связи |
| Entity Relationship | `erDiagram` | Схема БД: таблицы, связи, ключи |
| Pie | `pie` | Круговая диаграмма долей (статусы, бюджет) |
| Gantt | `gantt` | Задачи, сроки, зависимости, вехи |
| GitGraph | `gitGraph` | Ветвление Git: коммиты, ветки, слияния, теги |
| Mindmap | `mindmap` | Иерархия идей, требований, структуры проекта |
| Timeline | `timeline` | Временная шкала событий и вех |
| XY Chart | `xychart-beta` | Гистограммы, линейные/смешанные графики с осями |
| User Journey | `journey` | Путь пользователя: шаги, эмоции, роли |
| Quadrant | `quadrantChart` | Матрица 2×2 (приоритеты, риски, срочность/важность) |
| Requirement | `requirementDiagram` | Трассировка требований к элементам системы |
| Sankey | `sankey-beta` | Потоки объёмов между узлами |
| C4 Context | `C4Context` | Система и её окружение (люди, внешние системы) |
| Block | `block-beta` | Структурная схема из блоков и соединений |
| Packet | `packet-beta` | Сетевые пакеты и протоколы |
| Kanban | `kanban` | Доска: колонки, задачи, приоритеты, исполнители |
| Architecture | `architecture-beta` | Сервисная архитектура с иконками и группами |
| ZenUML | `zenuml` | Альтернативный синтаксис sequence |
| Radar | `radar-beta` | Радарная (паутинная) диаграмма |
| Venn | `venn-beta` | Пересечения множеств |
| Ishikawa (Fishbone) | `ishikawa-beta` | Анализ причин |
| Wardley Map | `wardley-beta` | Стратегическая карта ценности |
| TreeView | `treeview-beta` | Иерархическое дерево |

## Практический вывод
Перед тем как принять план/спеку/архитектуру от ИИ — попроси у него Mermaid-диаграмму
подходящего типа (не только flowchart) и проверяй ЕЁ, а не тысячи строк текста. Так ловятся
именно «додуманные» компоненты и незаданные требования. Подбор типа под задачу: поток →
sequence, состояния → stateDiagram, БД → erDiagram, требования → requirementDiagram,
приоритеты → quadrantChart, причины сбоя → ishikawa, стратегия → wardley.
